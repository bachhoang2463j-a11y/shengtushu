# 性能优化与书库数据出口（1.3.0）

## 使用入口

- 书架单本书菜单：**导出 TXT**、**备份本书**。
- 设置 → **数据管理**：**备份全部书籍**、**从备份导入**。
- 导出完成后选择 **另存到…**（Android 系统文件保存器）或 **系统分享**。未另存的临时导出文件会在离开页面时清理，不会覆盖原始 TXT/DOCX。
- 恢复为新书，同名也不覆盖。恢复不会自动生图。

### 格式与范围

TXT 是 UTF-8 当前正文出口，包含章节标题与正文，不包含图片/进度。

ZIP 格式标识为 `shengtushu_archive`，`formatVersion=1`：

```
manifest.json
books/<包内书籍id>/book.json
books/<包内书籍id>/images/<插图id>_cur.<格式>
books/<包内书籍id>/images/<插图id>_h<顺序>.<格式>
```

书籍包保留章节原文（含空段）、作者、设定说明、阅读进度、插图提示词/锚点、当前图和全部历史图的顺序。图片字节不变，不重新转码。恢复时重建数据库 id 和本机路径，不重新分章。包不包含原始导入文件路径、工作流、API 凭据、朗读参考音频及应用配置；这些配置迁移为后续范围。

备份不加密，正文、设定和提示词可能包含私人内容，分享前请确认接收方。

### 保护与限制

- 导入、生图、编辑等写入任务未结束时不能备份/恢复；传输期间阻止新的冲突写入。不停止 ComfyUI。
- 导入先校验再写入；数据库失败回滚，文件失败只清理本次新建目录，不清理原书库。
- 校验格式、路径、重复 id/引用、文件 CRC、缺失图片、符号链接和解压规模；缺图会报错，不静默生成不完整包。
- 单个结构化 JSON 上限 32 MiB，解压总量上限 4 GiB，条目上限 50,000。过大书库可分书备份；限制不改变原始数据。
- 图片删除、历史版本切换、生图工作流语义保持不变。正文删空和选区锚点算法不在本次调整范围。

## 性能实现

- 书架用数据库 `COUNT / GROUP BY` 统计，和阅读进度的监听解耦。
- 目录只读取 id/顺序/标题；正文只保留当前章并监听更新。章节请求与分页均有代次校验，等长正文修改也失效缓存。
- 一次 TextPainter 测量同时提供分页与连续流高度，批次先提供可读页面；历史进度恢复等待目标段落排好，未完成时显示“排版中”。
- 统一内容宽高、页眉页脚与段前距测量，防止页尾溢出；切章创建新的滚动/翻页控制器。
- 阅读图及网格缩略图按显示尺寸 × 设备像素比解码；高清查看继续读取原图。
- 当前章拆段与图片历史解析缓存；时钟只刷新局部。

### 已知边界与后续测试缺口

- ZIP 的条目数上限在第三方解码器读取中央目录之后检查；该上限不代表对解析阶段峰值内存的严格保证。只导入可信来源的备份。
- 导出查询依赖本应用写入时保证的章节 `idx` 顺序；当前导入路径均生成递增序号，手工改库造成的重复序号跨批导出不在本轮支持范围。
- 主机回归覆盖了归档往返、取消/失败回滚和非法路径；显式 CRC 篡改负例、正向段中锚点偏移、TXT 取消与系统保存完整交互仍可补充。

## 开发验证命令

在项目根目录执行：

```sh
flutter analyze
flutter test test --concurrency=1 --timeout 60s
flutter build apk --release
```

雷电已有书库时，只使用手动 `adb -s emulator-5554 install -r <APK>` 覆盖安装；失败即停止，不卸载、不清数据。Flutter 3.44.6 的设备集成测试默认结束后卸载应用，自动安装失败时也可能先卸载再重试，因此不能直接在有用户数据的设备上运行 `flutter test integration_test/... -d ...`。`--no-uninstall` 只关闭结束后的卸载，不能消除安装阶段的卸载兜底。

`integration_test/history_e2e_test.dart` 会临时修改应用设置并写入测试图，留给无用户数据的专用测试环境。`integration_test/performance_e2e_test.dart` 使用内存库及 mock 设置；需要 Profile 时使用 `flutter build apk --profile --target integration_test/performance_e2e_test.dart` 单独构建，手动保数据安装后通过 `flutter drive --use-existing-app <VM Service URL> --driver <integrationDriver脚本>` 附加收集。不要将 `flutter test --profile` 记为 Profile 测量，该命令的设备测试路径强制 debug。

Windows 下不要同时跑多条 Flutter 构建/测试命令：native assets 的 sqlite3.dll 可能被另一个测试进程占用。
